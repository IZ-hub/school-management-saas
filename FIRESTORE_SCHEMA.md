# Firestore Database Schema

This document describes the Firestore database structure for the School Management SaaS platform.

## Collection Structure

### schools
```typescript
{
  id: string,                    // Auto-generated by Firestore
  name: string,
  slug: string,                  // Unique identifier
  domain: string | null,         // Unique custom domain
  logo: string | null,           // URL to logo image
  address: string,
  phone: string,
  email: string,
  website: string | null,
  status: 'ACTIVE' | 'SUSPENDED' | 'TRIAL' | 'EXPIRED',
  subscriptionPlan: 'FREE' | 'BASIC' | 'PROFESSIONAL' | 'ENTERPRISE',
  subscriptionEnd: Timestamp | null,
  settings: object,             // JSON object for school-specific settings
  createdAt: Timestamp,
  updatedAt: Timestamp
}
```

### users
```typescript
{
  id: string,                    // Auto-generated by Firestore
  schoolId: string,              // Reference to schools collection
  email: string,
  password: string,              // Hashed password
  firstName: string,
  lastName: string,
  phone: string | null,
  avatar: string | null,        // URL to avatar image
  role: 'SUPER_ADMIN' | 'SCHOOL_OWNER' | 'PRINCIPAL' | 'VICE_PRINCIPAL' | 'ACCOUNTANT' | 'TEACHER' | 'PARENT' | 'STUDENT',
  status: 'ACTIVE' | 'INACTIVE' | 'SUSPENDED' | 'PENDING',
  lastLogin: Timestamp | null,
  emailVerified: boolean,
  mfaEnabled: boolean,
  mfaSecret: string | null,
  permissions: array,           // Array of permission strings
  createdAt: Timestamp,
  updatedAt: Timestamp
}
```

**Indexes:**
- Composite index on `schoolId` + `email`
- Single index on `schoolId`
- Single index on `email`

## Security Rules

Firestore security rules should be configured to ensure:
1. Multi-tenant isolation: All queries must include `schoolId` filter
2. Role-based access: Users can only access data appropriate to their role
3. Data validation: All writes must pass validation rules
4. Authentication: All operations require authenticated users

## Data Migration Strategy

When migrating from Prisma/PostgreSQL to Firestore:
1. Export existing data from PostgreSQL
2. Transform data to match Firestore schema
3. Import data using Firebase Admin SDK
4. Create required indexes
5. Set up security rules
6. Test data integrity
